OAS Service

The OAS Microservice is a tool for consumer-driven contract testing (CDCT). It is used when you cannot run tests on the provider side directly. Instead of setting up a provider test, you can test your consumer contract against the provider's OpenAPI Specification (OAS/Swagger) file.

The code can be found here.

When to use it

Use this if all of the following are true:

  • You have a consumer you want to test against a provider
  • You cannot set up a provider test using the standard CDCT method
  • You have access to the provider's OAS URL
  • The provider has a stable name in the Pact contract.
i

The OAS Service must be able to access the provider’s OAS file. If the OAS is only available inside an internal network, the OAS Service must also be deployed inside that network or in a cluster with access to it. A publicly hosted OAS Service cannot validate an OAS file that is only available internally.

For instructions on deploying the Pact Broker and OAS Service, see the infrastructure setup guide.

Do not use the OAS URL directly as the Pact provider name. URLs may contain characters such as / and :, which can cause problems when Pact writes the contract file.

Instead, use a filesystem-safe provider name:

const pact = new Pact({
    consumer: "Frontend",
    provider: "[URL...]-swagger.json",
    dir: path.resolve(process.cwd(), "pacts")
});

The actual OAS URL is passed separately when the webhook is created:

https://[provider-url]/swagger/v1/swagger.json

How does it work?

The microservice takes a Pact contract and compares it against the provider's swagger.json file.

Every time the consumer publishes a contract to the Pact Broker, the broker fires a webhook to the OAS Microservice with three values: providerUrl, pactUrl, and publishVerificationResult.

  • providerUrl: the actual URL of the provider’s OAS file
  • pactUrl: the URL of the published Pact contract
  • publishVerificationResult: whether the result should be published back to the Broker

From there:

  1. Resolve(providerUrl) is called to check whether the URL is a valid absolute URL pointing to a Swagger endpoint.
  2. Two things can happen:
    • If the URL cannot be resolved, the microservice skips the comparison and tells the broker the webhook ran successfully.
    • If the URL resolves, Compare() is called.
  3. Compare() fetches both the OAS and the Pact as JSON and compares them.
  4. The result is sent back to the Pact Broker as a verification result, where it becomes visible in the broker UI.

How to use it

The OAS Service can be run locally for testing or deployed inside an organisation for use with internal APIs.

Run locally with Docker

From the root of the repository, run:

docker compose up --build

The OAS Service will be available at:

http://localhost:8080

The Swagger interface is available at:

http://localhost:8080/swagger

To stop the service, run:

docker compose down
i

The Docker container must be able to access both the Pact contract and the provider’s OAS file.

If both services run in Docker Compose, use the provider’s Compose service name.

Deploy inside an organisation

If the provider’s OAS file is only available inside an internal network, the OAS Service must also be deployed in a network or cluster that can access it.

For deployment instructions, see the infrastructure setup guide.

Create the webhook

After the consumer publishes its Pact contract, create a webhook that sends the contract and OAS URLs to the OAS Service.

Add the following step to the consumer’s CI pipeline:

- name: Create OAS webhook
  uses: PracticalPact/pactbroker-webhook-action/webhook-OAS-action@main
  with:
    brokerUrl: ${{ vars.BROKER_URL }}
    providerName: [provider-name]
    oasUrl: https://[provider-url]/swagger/v1/swagger.json
    oasServiceUrl: https://[oas-service-url]

The values are:

  • brokerUrl: the URL of the Pact Broker
  • providerName: the provider name used in the Pact contract
  • oasUrl: the full URL of the provider’s OAS file
  • oasServiceUrl: the URL of the deployed OAS Service

The action creates a webhook for the consumer-provider pair. When the contract changes, the Pact Broker sends a request to the OAS Service:

{
  "events": [
    {
      "name": "contract_content_changed"
    }
  ],
  "request": {
    "method": "POST",
    "url": "https://[oas-service-url]/compare-from-webhook",
    "headers": {
      "content-type": "application/json",
      "accept": "application/json"
    },
    "body": {
      "providerUrl": "https://[provider-url]/swagger/v1/swagger.json",
      "pactUrl": "${pactbroker.pactUrl}",
      "publishVerificationResult": true
    }
  }
}

The OAS Service compares the contract with the OAS file and publishes the verification result back to the Pact Broker.
