Writing Consumer Tests for Gateways

Writing tests for a provider behind a gateway is done mostly in the same way as writing for the provider directly. See this guide for instructions on that. Besides that, take the following sections into account for some minor modifications.

Writing Tests

The big difference is that the tests of course need to be written to fit what the gateway expects. If it for example transforms endpoints or cookies, you must write the tests to fit the gateway, not to test the final provider. This is good news; it’s how your Consumer works in production anyway. This means you can test the exact behaviour of your real application.

For example, if the gateway takes a JOSSO cookie and turns it into an x-session header for the Provider, you write your tests with the JOSSO cookie; not the x-session header.

Provider Name

When configuring the Provider name for the test, you write the name of the gateway followed by -> and then the provider name. So if the name of the provider is ds-favorite and the name of the gateway is ds-dli-webapi-gateway , you write the name ds-dli-webapi-gateway->ds-favorite.
