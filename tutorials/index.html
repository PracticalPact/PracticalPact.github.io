Introduction to Tutorials

This guide takes you through the implementation of Consumer-Driven Contract Testing (CDCT) for a Consumer, a Provider, or both. If you are unfamiliar with these terms, read this short introduction to CDCT before continuing.

First, decide whether you want to implement CDCT for a Consumer or a Provider. Then choose a service that you understand well and that fulfils the chosen role. The examples below can help you decide.

If you are unsure which role to choose, start with the service you understand best and select the option that describes how it behaves in the interaction.

i

If you want to implement CDCT for both Consumers and Providers, we recommend starting with the Provider tutorial and then continuing with the Consumer tutorial.

Choose a role

Is your service a Consumer, a Provider, or both?

C

Consumer

A Consumer makes requests to a Provider. It initiates the interaction by sending HTTP requests.

Examples include:

  • Front-end applications
  • Websites
  • Mobile applications
  • Services that call other services
P

Provider

A Provider receives requests from a Consumer. It processes or retrieves data and sends a response back to the Consumer.

Examples include:

  • APIs
  • Back-end services
  • Services that expose data or functionality
B

Both

A service can interact with several other services, but in each individual interaction it acts as either a Consumer or a Provider.

For example, a Backend for Frontend may be a Provider for a front-end application while also being a Consumer of other back-end services.

In this situation, start by choosing one interaction and identify the role that the service has within that interaction.
