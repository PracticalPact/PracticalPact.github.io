Creating Contracts

Goal

A contract should describe one real interaction between a consumer and a provider.

Input

  • The API endpoint used by the consumer
  • The request method, path, headers, and body
  • The expected provider response

Steps

  1. Identify a real API call made by the consumer.
  2. Define the expected request.
  3. Define the expected response.
  4. Write a consumer test using a Pact mock provider.
  5. Run the test to generate the contract.
  6. Review the generated contract before publishing.

Decision points

  • If the interaction is not used by the consumer, do not create a contract.
  • If the response contains dynamic values, use matchers instead of fixed values.
  • If sensitive data appears in the contract, replace it with safe test data.

Output

A contract that captures the consumer’s expectations of the provider.
