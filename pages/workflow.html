Development Workflow and Team Coordination

Goal

CDCT should fit into normal development work instead of becoming a separate manual process.

Consumer team responsibilities

  • Define the API expectations they actually rely on
  • Maintain consumer contract tests
  • Publish new contracts when expectations change

Provider team responsibilities

  • Verify contracts from consumers
  • Investigate failed contract verifications
  • Coordinate breaking API changes with affected consumers

Decision points

  • If a provider change breaks a contract, the provider team must either adapt the API or coordinate with the consumer.
  • If a consumer adds a new expectation, the provider team must verify whether the provider supports it.
  • If several teams depend on one service, contract changes should be reviewed before deployment.

Output

A clearer workflow for maintaining service compatibility across teams.
