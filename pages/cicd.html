CI/CD Integration

CI/CD automates how software is built, tested, and released. It provides fast feedback on code changes and helps teams apply the same checks every time.

What is CI/CD?

CI

Continuous Integration

Continuous Integration automatically builds and tests the code whenever developers make changes. This helps teams find errors before the changes are merged or released.

CD

Continuous Deployment

Continuous Deployment extends this process by preparing or deploying tested changes to an environment. This reduces manual work and makes releases more consistent.

Why is CI/CD important?

CI/CD is especially useful in systems with several services and development teams. Services can be changed and released independently, so each change must be checked against the rest of the system.

  • Provides fast feedback on code changes
  • Runs the same checks for every release
  • Reduces manual work and human error
  • Makes it easier to release changes more often

How CDCT fits into CI/CD

CDCT with Pact is designed to run as part of the normal CI/CD workflow. Consumer tests run in the Consumer repository, while Provider verification runs in the Provider repository.

1

Consumer pipeline

The Consumer runs its contract tests and publishes the generated contracts to the Pact Broker.

2

Provider pipeline

The Provider retrieves the published contracts, verifies them, and publishes the verification results to the Pact Broker.

3

Deployment check

Before deployment, the pipeline asks the Pact Broker whether the application version is compatible with the versions already running in the target environment.

This makes contract testing part of the normal development and deployment process instead of a separate manual activity.

Practical Pact GitHub Actions

Practical Pact provides GitHub Actions that simplify several parts of the CI/CD setup used by this method.

  • Publishing contracts to the Pact Broker
  • Checking whether an application version can be deployed
  • Recording deployments in the Pact Broker
  • Creating and managing Pact Broker webhooks
i

The actions are examples and may need to be adapted to match your organisation’s CI/CD platform, repository structure, security requirements, and infrastructure.

See the Practical Pact GitHub repository for the available actions. Each action is documented in its own README file.
